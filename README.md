## 티켓 발급 동시성 제어 및 비동기 처리

초과 발급 문제를 재현하고 비관적 락,비동기 메시지 처리 읽기,쓰기 분리를 단계적으로 구현
이후 RabbitMQ로 요청 접수와 발급 처리를 분리하고 MYSQL 복제와 읽기,쓰기 분리.

`2026.10` | 개인 프로젝트 

### 프로젝트 범위

동시 발급 시 초과 발급 및 재고 불일치 재현
비관적 락을 이용한 동일 티켓의 동시 변경 제어
RabbitMQ를 이용한 비동기발급
MYSQL A->B 복제 및 트랜잭션 기반 읽기,쓰기 연결 분리 
### 기술 스택

Java 21, Spring Boot, JPA, MYSQL, RabbitMQ, Docker, k6, JUnit 

### 구현 및 검증

**비동기 발급:** RabbitMQ로  요청 접수와 발급 처리를 분리하고, 접수 응답과 DB의 발급 결과를 구분하여 확인하였습니다.

**읽기,쓰기 분리:** MySQL 복제와 읽기와 쓰기를 구분하여 읽기용 DB와 생성,발급용 DB로 분리하였습니다.

### 문제해결

**동시 발급으로 인한 재고 불일치**

**문제:** 재고 100장에 동시 발급 요청을 보낸 경우 초과 발급과 재고 불일치가 발생했습니다. 여러 트랜잭션이 동일한 재고를 조회한 뒤 변경하면서 갱신 내용이 덮어 써지는 현상을 확인했습니다.

**해결:** 티켓 발급  대상 조회에 비관적 락을 적용하여 티켓의 동시 변경을 제어 하였고, 재고 차감과 발급 내역 저장을 하나로 트랜잭션으로 처리하였습니다.

**결과**:  재고 100장에 1000건의 동시 발급  요청을 보내는 테스트에서 발급 내역 100건과 잔여 재고 0장을 확인했습니다.
